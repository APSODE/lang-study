# 한자 묶음 번역 지침 (번역 에이전트용)

여러 에이전트가 묶음을 하나씩 따로 맡는다. 결과가 서로 일관되도록 **이 지침을 그대로** 따른다.
모르는 것을 지어내지 않는다. 애매하면 아래 규칙의 "기본값"을 쓴다.

## 맡은 일

입력: `content-src/kanji/batches/<묶음>.json` (예: `n4-02.json`) — 한자 객체 배열.
출력: 같은 폴더의 `<묶음>.ko.json` (예: `n4-02.ko.json`).

각 객체에서 **두 필드만** 채운다.

| 필드 | 입력 값 | 채울 값 |
|---|---|---|
| `meanings_ko` | `[]` | 한국어 뜻 1–4개 (문자열 배열) |
| `hunum_ko` | `""` | 전통 훈음 하나 (예: `"먹을 식"`), 없으면 `""` 그대로 |

### 바꾸면 안 되는 것

- 다른 필드(`kanji`, `on`, `kun`, `eum_ko`, `meanings_en`, `jlpt`, `strokes`, `freq`)는 **값 하나도 바꾸지 않는다.** 읽기에 오타가 있어 보여도 고치지 않는다.
- 객체를 추가 · 삭제 · 순서 변경하지 않는다. 키를 추가하지 않는다(메모 · 주석 금지).
- 입력 파일(`<묶음>.json`)은 수정하지 않는다.
- 출력 형식: 입력과 같이 들여쓰기 2칸, 키 알파벳 순서, UTF-8, 한글을 `\uXXXX` 로 바꾸지 않는다, 파일 끝 줄바꿈 하나.
  Python 이면 `json.dumps(data, ensure_ascii=False, indent=2, sort_keys=True) + "\n"`.

## meanings_ko 규칙

1. **1–4개.** 가장 흔한 뜻을 맨 앞에. 보통 1–3개면 충분하다. 4개를 채우려고 억지로 늘리지 않는다.
2. **일본어에서 이 한자가 실제로 쓰이는 뜻**을 기준으로 한다. `meanings_en` 과 훈독(`kun`)은 힌트일 뿐이다.
   - `meanings_en` 의 드물거나 옛 뜻, 부수 설명(`"one radical (no.1)"`), 인명용 설명, `"(kokuji)"` 같은 표시는 번역하지 않는다.
   - 영어 뜻 여러 개가 한국어로 같은 말이 되면 하나로 합친다 (`"power", "strength"` → `"힘"`).
3. **형태**
   - 동작 · 상태는 사전형: `"먹다"`, `"높다"`, `"조용하다"`, `"가르치다"`.
   - 사물 · 개념은 명사: `"물"`, `"음식"`, `"시간"`, `"나라"`.
   - 수사는 숫자 이름: `"하나"`, `"여섯"`. 단위 · 조수사는 `"~개(물건 세는 말)"` 처럼 짧게 설명해도 된다.
   - 한 항목은 짧게: 낱말 하나 또는 2–3어절. 문장 · 마침표 · 따옴표 · 영어 · 한자를 넣지 않는다.
   - 괄호는 꼭 필요할 때만, 구별용으로 짧게: `"단(段, 계단)"` 대신 `"계단"`, 꼭 필요하면 `"줄(행)"` 정도.
4. 같은 항목을 두 번 쓰지 않는다. 앞뒤 공백 없이 쓴다.
5. 한국 한자어로 바꿀 수 있어도, 학습자가 바로 알아듣는 **쉬운 말**을 먼저 쓴다 (`"생활하다"` 보다 `"살다"`).

## hunum_ko 규칙

1. 한국 옥편식 **전통 훈음 하나**: `"<훈> <음>"`. 예: `"먹을 식"`, `"물 수"`, `"배울 학"`, `"돌아올 회"`.
   - 훈과 음 사이는 공백 하나. 음은 **한글 한 음절**.
   - 여러 훈음이 있으면 **하나만** 쓴다. 쉼표로 둘 이상 적지 않는다.
2. **음(마지막 음절)은 반드시 `eum_ko` 에 있는 음 중 하나**여야 한다. 그대로 복사한다.
   - `eum_ko` 의 순서는 대표성과 무관하다. 그 한자의 **가장 대표적인 표준 훈음**을 고른다: `金`(`"김, 금"`) → `"쇠 금"`, `不`(`"부, 불"`) → `"아닐 불"`, `女`(`"녀, 여"`) → `"여자 녀"`. 본음과 두음법칙 형이 둘 다 있으면 본음(`녀`, `력`, `륙`)을 쓴다.
   - `eum_ko` 에 없는 음(두음법칙 변형 포함)을 쓰지 않는다. 표준 훈음의 음이 `eum_ko` 에 없으면, `eum_ko` 의 음에 맞는 다른 표준 훈음을 쓰고, 그런 것이 없으면 `""` 로 둔다.
3. 훈은 **흔히 쓰이는 표준 훈**(한자능력검정 · 교육용 한자 표기)을 쓴다. 일본어 뜻에 맞추려고 훈을 새로 만들지 않는다.
4. **`""` 로 두는 경우 (지어내지 않는다)**
   - `meanings_en` 에 `"(kokuji)"` 가 있는 国字(일본에서 만든 글자). `eum_ko` 가 있어도 **항상 `""`**.
   - `eum_ko` 가 `""` 인 경우.
   - 표준 훈음을 확실히 모르는 경우.

## 예시

입력 (`n5-01.json` 의 `食`, 필드 일부 생략):
```json
{ "eum_ko": "식, 사", "hunum_ko": "", "kanji": "食", "kun": ["く.う", "く.らう", "た.べる", "は.む"],
  "meanings_en": ["eat", "food"], "meanings_ko": [], "on": ["ショク", "ジキ"] }
```
출력: `"meanings_ko": ["먹다", "음식"]`, `"hunum_ko": "먹을 식"` — 흔한 경우. 음 `식` 은 `eum_ko` 의 첫 음.

입력 (`生`, 뜻이 여럿):
```json
{ "eum_ko": "생", "kanji": "生", "kun": ["い.きる", "う.まれる", "は.える", "なま", "…"],
  "meanings_en": ["life", "genuine", "birth"] }
```
출력: `"meanings_ko": ["살다", "태어나다", "날것", "삶"]`, `"hunum_ko": "날 생"` — 영어 뜻은 3개뿐이지만 훈독(生きる · 生まれる · 生)에서 일본어의 주요 뜻을 고르고, 흔한 순서로 4개 이내.

입력 (`楽`, 대표 음이 `eum_ko` 의 첫 음이 아님):
```json
{ "eum_ko": "락, 악", "kanji": "楽", "kun": ["たの.しい", "たの.しむ", "この.む"],
  "meanings_en": ["music", "comfort", "ease"] }
```
출력: `"meanings_ko": ["즐겁다", "편하다", "음악"]`, `"hunum_ko": "즐길 락"` — 일본어에서는 "즐겁다 · 편하다"가 주된 뜻이므로 그 순서. 훈음은 대표 훈음 `"즐길 락"` (`"노래 악"` 도 표준이지만 덜 대표적).

입력 (`込`, 国字):
```json
{ "eum_ko": "입", "kanji": "込", "kun": ["こ.む", "こ.める", "…"],
  "meanings_en": ["crowded", "mixture", "in bulk", "included", "(kokuji)"], "on": [] }
```
출력: `"meanings_ko": ["붐비다", "넣다", "포함하다"]`, `"hunum_ko": ""` — `"(kokuji)"` 이므로 `eum_ko` 가 있어도 훈음은 비운다. 뜻은 込む(붐비다) · 込める(넣다, 담다) · 込み(포함) 의 일본어 쓰임에서.

## 끝내기 전 스스로 확인

- [ ] 출력 파일 이름이 `<묶음>.ko.json` 이고 입력과 같은 폴더에 있다. 입력 파일은 그대로다.
- [ ] 객체 수 · 순서 · `kanji` 값이 입력과 같다.
- [ ] `meanings_ko`, `hunum_ko` 외에 바뀐 값 · 추가된 키가 없다 (`diff` 로 두 필드 줄만 바뀌었는지 본다).
- [ ] 모든 `meanings_ko` 가 한글 1–4개, 빈 문자열 · 중복 · 앞뒤 공백 · 영어 · 한자 · 마침표가 없다.
- [ ] 동사 · 형용사는 `~다` 사전형, 사물은 명사다. 첫 항목이 가장 흔한 뜻이다.
- [ ] 모든 `hunum_ko` 는 `""` 이거나 `"<훈> <음>"` 이고, 음이 `eum_ko` 의 음 중 하나다.
- [ ] `"(kokuji)"` 한자와 `eum_ko` 가 `""` 인 한자는 `hunum_ko` 가 `""` 다.
- [ ] 들여쓰기 2칸, 키 정렬, `ensure_ascii=False`, 파일 끝 줄바꿈 하나. JSON 으로 다시 읽힌다.
- [ ] 가능하면 `python3 -I tools/kanji/merge.py` 를 돌려 자기 묶음에 오류가 없는지 본다 (경고 "hunum_ko 가 비었음"은 일부러 비운 것이면 괜찮다).
