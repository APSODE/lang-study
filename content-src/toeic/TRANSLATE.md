# 토익 단어 묶음 번역 지침 (번역 에이전트용)

여러 에이전트가 묶음을 하나씩 따로 맡는다. 결과가 서로 일관되도록 **이 지침을 그대로** 따른다.
모르는 것을 지어내지 않는다. 애매하면 아래 규칙의 "기본값"을 쓴다.

## 맡은 일

입력: `content-src/toeic/batches/<묶음>.json` (예: `tsl-03.json`) — 단어 객체 배열 (TOEIC Service List, 빈도 순).
출력: 같은 폴더의 `<묶음>.ko.json` (예: `tsl-03.ko.json`).

각 객체에서 **네 필드만** 채운다.

| 필드 | 입력 값 | 채울 값 |
|---|---|---|
| `pos` | `""` | 품사 약호 (첫 뜻의 품사), 예: `"n"`, `"v"`, `"n, v"` |
| `meaning_ko` | `""` | 한국어 뜻 1–3개를 `", "` 로 이은 문자열, 예: `"송장, 청구서"` |
| `example_en` | `""` | 영어 업무 · 생활 예문 하나 (표제어를 철자 그대로 포함) |
| `example_ko` | `""` | `example_en` 의 자연스러운 한국어 번역 |

이 데이터는 앱의 두 문제에 그대로 쓰인다. 규칙이 엄격한 이유다.
- **뜻 문제**: 단어를 보여주고 한국어 뜻을 입력 · 선택하게 한다. 학습자가 `meaning_ko` 의 **항목 하나만** 입력해도 정답이다
  (쉼표로 나눈 각 항목을 따로 비교, 괄호 안 내용과 공백은 무시).
- **빈칸 문제**: `example_en` 에서 표제어를 `_____` 로 가리고 단어를 입력하게 한다. 정답은 표제어 철자 그대로다.

### 바꾸면 안 되는 것

- 다른 필드(`word`, `rank`, `list`, `sfi`, `u`, `forms`)는 **값 하나도 바꾸지 않는다.** 철자가 이상해 보여도 고치지 않는다
  (`headquarter`, `pant`, `sightsee` 처럼 목록의 표제어 형태가 특이한 것도 그대로 둔다).
- 객체를 추가 · 삭제 · 순서 변경하지 않는다. 키를 추가하지 않는다(메모 · 주석 금지).
- 입력 파일(`<묶음>.json`)은 수정하지 않는다.
- 출력 형식: 입력과 같이 들여쓰기 2칸, 키 알파벳 순서, UTF-8, 한글 · 악센트 문자를 `\uXXXX` 로 바꾸지 않는다, 파일 끝 줄바꿈 하나.
  Python 이면 `json.dumps(data, ensure_ascii=False, indent=2, sort_keys=True) + "\n"`.

`forms` 는 참고용 변화형(복수형 · 과거형 등)이다. 품사를 짐작하는 데 쓴다. 예문에는 쓰지 않는다(아래 example_en 규칙).

## meaning_ko 규칙

1. **1–3개**, `", "`(쉼표 + 공백 하나)로 잇는다. 보통 1–2개면 충분하다. 3개를 채우려고 억지로 늘리지 않는다.
2. **토익 · 업무에서 쓰이는 뜻을 맨 앞에.** 일상적인 뜻이 더 흔해도 토익 지문(사무실 · 회의 · 출장 · 쇼핑 · 계약 · 채용)에서
   쓰이는 뜻이 먼저다. 예: `outstanding` → `"미지불의, 뛰어난"`, `lease` → `"임대차 계약, 임대하다"`.
   - 뜻이 많은 단어는 토익에서 잘 쓰이는 것만 3개 이내로 고르고 나머지는 버린다.
3. **각 항목은 혼자서 정답이 될 수 있어야 한다.** 학습자가 항목 하나만 입력해도 맞게 처리되므로:
   - 앞 항목에 기대는 말을 쓰지 않는다 (`"청구서, 그것을 보내다"` ✗).
   - 쉼표는 항목 구분에만 쓴다. 한 항목 안에 쉼표 · `;` · `·` · `/` 를 넣지 않는다 (`"송장/청구서"` ✗ — 채점기가 나눠 버린다).
   - 같은 말을 두 번 쓰지 않는다 (`"예약, 예약"` ✗, `"주문, 주문(하다)"` ✗ — 괄호를 빼면 같다).
4. **형태**
   - 명사는 명사: `"고객"`, `"송장"`, `"마감일"`.
   - 동사는 사전형 `~다`: `"연기하다"`, `"알리다"`, `"제출하다"`.
   - 형용사: 서술어로 자연스러우면 사전형 `~다` (`"편리하다"`, `"유효하다"`, `"긴급하다"`).
     서술어가 어색한 관계 형용사는 `~의` / `~적인` (`"야외의"`, `"연례의"`, `"전기의"`, `"행정의"`).
   - 부사는 부사: `"곧"`, `"즉시"`, `"정확하게"`, `"매년"`.
   - 한 항목은 짧게: 낱말 하나 또는 2–3어절. 문장 · 마침표 · 따옴표 · 영어 · 한자를 넣지 않는다.
   - **괄호는 꼭 필요할 때만**, 뜻을 좁히는 짧은 말로: `"(문제를) 다루다"`, `"(비용을) 부담하다"`. 괄호 안은 채점에서
     무시되므로, **괄호를 뺀 나머지만으로도 말이 되고 한글이 남아야** 한다 (`"(예약)"` 혼자 ✗).
5. 한국 토익 학습자가 바로 알아듣는 **흔한 말**을 쓴다. 뜻이 정확한 것이 먼저이고, 그 안에서 쉬운 말을 고른다
   (`refund` → `"환불"`, `"반환금"` 보다).

## pos 규칙

- 약호는 이것만: `n`(명사) `v`(동사) `adj`(형용사) `adv`(부사) `prep`(전치사) `conj`(접속사) `pron`(대명사) `det`(한정사) `num`(수사).
- **meaning_ko 의 첫 뜻의 품사**를 쓴다. 기본값은 하나.
- 앞쪽 뜻들이 두 품사에 걸치면(예: 첫 뜻이 명사, 둘째 뜻이 동사) `", "` 로 이어 쓴다: `"n, v"`. 순서는 뜻의 순서. 최대 3개, 중복 없음.
- 대문자 · 마침표를 쓰지 않는다 (`"N"`, `"n."`, `"noun"` ✗).

## example_en 규칙

1. **문장 하나**, 8–18 낱말, 대문자로 시작해 `.` `?` `!` 로 끝난다. 토익 지문 같은 자연스러운 업무 · 사무실 · 출장 · 서비스 상황.
2. **표제어 `word` 를 철자 그대로 온전한 낱말로 한 번 이상** 넣는다 (대소문자는 상관없음, 문장 첫머리면 대문자 가능).
   - 변화형만 쓰면 안 된다: `invoice` 인데 `invoices` · `invoiced` 만 있으면 ✗. 변화형이 자연스러운 문장이면 **문장을 바꿔서**
     원형을 쓴다 (`"The invoices were sent."` → `"Please send the invoice by Friday."`).
   - 표제어로 **시작하는 다른 낱말을 같은 문장에 쓰지 않는다.** 빈칸 처리가 그 낱말까지 가린다
     (`pan` 문장에 `panel`, `invoice` 문장에 `invoices` ✗). 표제어 자체는 한 번만 쓰는 것이 가장 좋다.
   - 악센트 · 하이픈 · 아포스트로피 · 띄어쓰기도 그대로: `résumé`(`resume` ✗), `café`, `e-book`, `ice cream`, `o'clock`.
     아포스트로피 · 따옴표는 **곧은 것**(`'` `"`)만 쓴다 (`o’clock` ✗ — 검사에서 표제어를 찾지 못한다).
   - 표제어 형태가 특이하면 그 형태가 문법에 맞게 쓰이는 문장을 만든다:
     `headquarter` → 동사 "본사를 두다" (`"…plans to headquarter its operations in…"`),
     `pant` → 수식어 (`"pant legs"`), `sightsee` · `fundraise` → 동사원형 (`"to sightsee"`).
3. 예문의 뜻은 `meaning_ko` 의 뜻 중 하나와 맞아야 한다(가능하면 첫 뜻).
4. 실제 회사 · 상표 · 유명인 이름을 쓰지 않는다. 사람이 필요하면 `the manager`, `our client` 같은 일반 명사나 `Ms. Park`, `Mr. Lee`
   처럼 흔한 성 하나만.
5. 한글을 넣지 않는다. 숫자 · 시간 · 금액은 써도 된다 (`$200`, `3 p.m.`).

## example_ko 규칙

- `example_en` 의 **자연스러운 한국어 번역** 한 문장. 직역투보다 실제 업무 문서 · 안내문 말투 (`~해 주십시오`, `~했습니다`).
- 표제어의 뜻이 번역문에 드러나게 한다 (가능하면 `meaning_ko` 의 항목과 같은 말로).
- 영어 낱말을 그대로 남기지 않는다 (흔히 쓰는 외래어 · 숫자 · `$` 는 괜찮다).

## 예시

입력 (`tsl-01.json` 의 `invoice`, 필드 일부 생략):
```json
{ "example_en": "", "example_ko": "", "forms": ["invoices", "invoiced", "invoicing"], "list": "TSL",
  "meaning_ko": "", "pos": "", "rank": 19, "word": "invoice" }
```
출력:
```json
"pos": "n",
"meaning_ko": "송장, 청구서",
"example_en": "Please send the invoice to the accounting department by Friday.",
"example_ko": "금요일까지 송장을 회계부로 보내 주십시오."
```
— 흔한 경우. 두 뜻 모두 명사이므로 `pos` 는 `"n"` 하나. 예문에 `invoices` 를 쓰지 않았다.

입력 (`outstanding`, 일상 뜻과 업무 뜻이 다름):
```json
"pos": "adj",
"meaning_ko": "미지불의, 뛰어난, 미해결의",
"example_en": "We must pay the outstanding balance before the end of this month.",
"example_ko": "이번 달 말 전에 미지불 잔액을 지불해야 합니다."
```
— 일상에서는 "뛰어난"이 더 흔해도, 토익에서 자주 나오는 "미지불의"가 먼저. "미지불의"는 서술어가 어색해서 `~의` 형.

입력 (`lease`, 앞쪽 뜻이 두 품사):
```json
"pos": "n, v",
"meaning_ko": "임대차 계약, 임대하다",
"example_en": "The company signed a five-year lease for the new office space.",
"example_ko": "회사는 새 사무 공간에 대해 5년 임대차 계약을 맺었다."
```
— 첫 뜻은 명사, 둘째는 동사라서 `"n, v"`. `leased` · `leasing` 은 쓰지 않았다.

입력 (`headquarter`, 표제어 형태가 특이함, `forms`: `headquarters` …):
```json
"pos": "n, v",
"meaning_ko": "본사, 본사를 두다",
"example_en": "The firm plans to headquarter its Asian operations in Singapore next year.",
"example_ko": "그 회사는 내년에 아시아 사업 본사를 싱가포르에 둘 계획이다."
```
— 목록의 표제어는 `headquarter` 이므로 `headquarters` 대신 동사로 쓰는 문장을 만들었다(뜻의 둘째 항목과 맞음).
  표제어 철자가 그대로 들어 있어 빈칸 문제가 된다.

## 끝내기 전 스스로 확인

- [ ] 출력 파일 이름이 `<묶음>.ko.json` 이고 입력과 같은 폴더에 있다. 입력 파일은 그대로다.
- [ ] 객체 수 · 순서 · `word` 값이 입력과 같다.
- [ ] `pos`, `meaning_ko`, `example_en`, `example_ko` 외에 바뀐 값 · 추가된 키가 없다 (`diff` 로 네 필드 줄만 바뀌었는지 본다).
- [ ] 네 필드 모두 비어 있지 않고 앞뒤 공백이 없다.
- [ ] `pos` 는 `n v adj adv prep conj pron det num` 중 하나, 또는 `", "` 로 이은 서로 다른 것들이다.
- [ ] `meaning_ko` 는 `", "` 로 이은 1–3개, 각 항목은 혼자서 뜻이 통하는 한국어, `; · /` · 영어 · 한자 · 마침표 없음, 괄호는 최소.
- [ ] 첫 뜻이 토익 · 업무 뜻이다. 명사는 명사, 동사는 `~다`.
- [ ] `example_en` 에 표제어가 **철자 그대로**(악센트 · 하이픈 · 곧은 아포스트로피 포함) 온전한 낱말로 들어 있다. 변화형만 있지 않다.
      표제어로 시작하는 다른 낱말이 없다. 8–18 낱말, 실제 회사 · 인물 이름 없음.
- [ ] `example_ko` 는 자연스러운 한국어 한 문장이다.
- [ ] 들여쓰기 2칸, 키 정렬, `ensure_ascii=False`, 파일 끝 줄바꿈 하나. JSON 으로 다시 읽힌다.
- [ ] `python3 -I tools/toeic/merge.py` 를 돌려 **자기 묶음** 줄에 오류(ERROR)가 없는지 본다. 경고(WARN)도 되도록 없앤다.
      (다른 묶음이 "번역 없음"으로 나오는 것은 괜찮다. 종료 코드 1 이면 어느 묶음의 오류인지 확인한다.)
