## 확정된 것

- **새 프로젝트**: 퀴즈 v2(`APSODE/quiz-launcher`)와 코드 · 계정을 공유하지 않는다. 퀴즈 v2의 설계(FSRS 사용, 서버 재채점, 초대 가입, 업로드 → 관리자 승인)는 참고만 한다.
- **목적**: JLPT 대비(한자), 일본어 가나(히라가나 · 가타카나), 일본어 회화, 토익, 토플.
- **사용자**: 본인과 친구들. 퀴즈 v2보다 인원이 적다.
- **기능**: 단어 SRS, 한자 읽기 등. 듣기(TTS)는 넣는다. **발음 평가는 나중에** 하되, 쉽게 추가할 수 있게 설계한다.
- **기술 스택**: 사용자는 상관없음 → 제안안(아래)으로 진행.
- **콘텐츠 출처**: AI 생성 + 공개 사전 + 친구 업로드 모두.
- **콘텐츠 저장**: DB에 보관하고 git에 주기적으로 동기화.
- **우선순위**: 1차 = 가나 · 한자 · 토익. 그 뒤에 JLPT 단어 · 회화 · 토플 · 발음.
- **프로젝트 이름**: NakamuraProject. 레포는 `APSODE/lang-study`(https://github.com/APSODE/lang-study).
- **git 동기화**: DB → git 단방향. 문제가 생기면 git의 JSON에서 DB로 복구하는 `import` 명령을 수동으로 실행한다(자동 양방향 동기화는 하지 않는다).
- **같이 쓰는 기능**: 연속 학습일(스트릭), 문항 신고, 친구 진도 보기, 리더보드.
  - 리더보드 기준(제안): 주간 복습 수 + 연속 학습일. 맞힌 비율은 쉬운 카드만 고르는 쪽으로 유도하므로 쓰지 않는다. 진도 · 리더보드 공개를 끄는 설정을 둔다.
- **가입**: 초대 링크(관리자가 발급, 만료 · 사용 횟수 제한).
- **하루 신규 카드**: 기본 15장, 사용자별 · 트랙별로 조정 가능(가나는 더 높게 둬도 된다). 복습 카드는 제한하지 않는다.

## 설계

### 기술 스택
| 영역 | 선택 |
|---|---|
| 프론트 | React + Vite + TypeScript, PWA(폰 홈 화면 설치, 매일 복습용) |
| 패키지 | npm 워크스페이스. 호스트에 Node 없이 `./nd`(node:26 컨테이너)로 개발 |
| 서버 | Hono + TypeScript (Node 26 타입 제거로 빌드 없이 실행) |
| DB | SQLite(`node:sqlite`, 네이티브 모듈 없음) |
| SRS | FSRS(`ts-fsrs`) |
| 일본어 입력 | wanakana(로마자 → 가나 변환) |
| 음성 | Opus 파일을 서버 저장소에 보관(git 제외) |

### 데이터 모델: 노트 × 연습 방식 = 카드
- **노트**: 내용 하나. 트랙별 필드.
  - 가나: `char, romaji, script(히라가나|가타카나), row, 탁음 · 요음 여부`
  - 한자: `kanji, on[], kun[], meanings_ko, jlpt, strokes, examples[]`
  - 토익 단어: `word, pos, meaning_ko, example_en, example_ko, list(TSL|NGSL)`
- **연습 방식(drill)**: 플러그인처럼 등록. `{ id, tracks, requires(필요한 필드), Prompt, Answer, grade() }`. 필요한 필드가 있는 노트에만 카드가 생긴다.
- **카드** = 노트 × 연습 방식. FSRS 상태는 사용자별 · 카드별.
- **발음 확장 지점**: `speak` 연습 방식 + 서버의 채점기 인터페이스 `Assessor`(구현체: 브라우저 음성 인식 / Azure 발음 평가). 음성 저장소는 듣기용으로 처음부터 있으므로 녹음도 같은 구조에 저장. 데이터 모델 · SRS · 화면 구조는 바꾸지 않는다.

### 콘텐츠 흐름
```
공개 사전 → 가져오기 스크립트 ┐
AI 생성 (PC에서 실행) ──────────┼→ 검사 → DB(초안) → 관리자 검토 → DB(공개)
친구 업로드 (JSON) ─────────────┘                               │
                                하루 1번 + 수동 → JSON으로 내보내 git 커밋 · push
```
- DB가 원본. 관리자 화면에서 편집, 수정 이력(`note_revisions`).
- git에는 콘텐츠만 트랙별 정렬된 JSON으로 내보낸다. 사용자 기록은 DB 백업으로 따로.
- 음성은 PC에서 생성(VOICEVOX — 출처 표기 필요, Piper / Kokoro), 서버에 올리고 DB에 기록. 1GB 서버에서는 생성하지 않는다.

### 배포 · 이전 (서버 미정 → 옮기기 쉽게)
서버는 미정이다. 1순위는 퀴즈 v2 서버(오라클 프리티어 AMD Micro, 1GB)에 함께 올리는 것이고, 자원이 모자라면 로컬 PC에서 돌린다. 그래서 **어디서든 같은 방식으로 띄우고, 디렉토리 하나만 옮기면 이전이 끝나게** 만든다.

- **프로세스 하나**: Hono가 API와 웹 정적 파일을 같이 낸다. 외부 서비스는 필수가 아니다. git push와 Azure는 설정이 없으면 꺼진다.
- **상태는 `DATA_DIR` 하나에**: `db/app.sqlite`, `audio/`, `backups/`. 코드와 이미지에는 상태를 두지 않는다.
- **설정은 환경 변수(`.env`)만**: `PORT`, `DATA_DIR`, `PUBLIC_URL`, `BASE_PATH`(하위 경로 배포 대비), `GIT_REMOTE`(비우면 내보내기 끔), `SESSION_SECRET`. 호스트별 차이는 `.env`에만 둔다.
- **시작 시 자동 마이그레이션**: 빈 `DATA_DIR`로 띄우면 스스로 초기화된다.
- **Docker 이미지 하나**: 퀴즈 v2와 같은 방식. PC(x86_64)에서 빌드 → `docker save | ssh … docker load`. 1GB 서버에서는 빌드하지 않는다. 로컬은 같은 compose 또는 `node`로 바로 실행.
- **자원 상한**: `NODE_OPTIONS=--max-old-space-size=192`, `mem_limit: 256m`. 퀴즈 v2(약 75MB, 상한 512m)와 함께 1GB + 스왑 2GB 안에 들어가게 한다. 무거운 작업(AI 생성, TTS 음성 생성)은 서버에서 하지 않는다.
- **포트**: `127.0.0.1:8081`에만 연다. 퀴즈 v2(8080)와 겹치지 않게. 공개는 리버스 프록시나 `tailscale serve`로 한다.
- **로컬 운영 시 친구 접속**: Tailscale(친구도 설치) 또는 Cloudflare Tunnel(설치 불필요, 도메인 필요) 중 선택.
- **이전 절차**: `export` 명령으로 `DATA_DIR` 묶음(SQLite는 `VACUUM INTO`로 일관된 사본) → 새 호스트에서 풀기 → `.env` 복사 → 실행 → 프록시나 터널 대상 변경.
- **DB → git 내보내기**: 서버에 deploy key가 있을 때만 앱이 push한다. 없으면 PC에서 `export` 후 수동 커밋으로 대체.
