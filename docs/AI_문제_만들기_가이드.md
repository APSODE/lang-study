# 문제 파일 만들기 가이드 (AI용)

> 이 문서는 사용자의 AI 비서가 읽는 명세다. 사용자가 원하는 주제로 학습 앱(NakamuraProject)에 올릴 **JSON 파일**을 만들어 준다.
> 서버 검사 규칙(`apps/server/src/uploads.ts`, `packages/core/src/validate.ts`)과 맞춰 썼다. 규칙을 어기면 그 카드만 빠지고 나머지는 올라간다.

## 0. 할 일 요약

1. 사용자에게 파일 종류를 정한다: **새 항목/기존 항목(앞뒤 카드)**, **한자 추가**, **토익 단어 추가** 중 하나. 파일 하나 = 종류 하나.
2. 아래 형식대로 JSON을 만든다. **카드 200개 이하**, 파일 1MB 이하.
3. 출력: JSON 하나만 코드 블록(```json)으로 준다. 사용자는 이것을 `.json` 파일로 저장해 앱의 **자료 → 문제 만들기 → 파일 올리기**에 올린다.
4. 올린 문제는 초안이 되고, 관리자가 공개해야 학습에 들어간다.

JSON 공통 규칙: 표준 JSON(주석 · 끝 쉼표 금지), UTF-8, 최상위는 객체 하나. **정해진 키 외의 키를 넣지 않는다**(모르는 키는 오류). `id` 는 넣지 않는다(서버가 만든다).

## 1. 앞뒤 카드 (새 항목 만들기 · 기존 항목에 추가)

아무 주제나 담을 수 있는 공통 카드. 학습 화면은 **앞면을 보여 주고 사용자가 뒷면을 직접 입력**한다. 입력이 뒷면과 같으면 자동 정답, 다르면 사용자가 모범 답안(뒷면)과 비교해 스스로 맞음/틀림을 고른다.

```json
{
  "deck": "일본어 회화 표현",
  "cards": [
    { "front": "잘 먹겠습니다", "back": "いただきます", "note": "식사 전 인사" },
    { "front": "수고하셨습니다 (퇴근 인사)", "back": "お疲れ様でした / おつかれさまでした" }
  ]
}
```

| 키 | 필수 | 규칙 |
|---|---|---|
| `deck` | O | 항목 이름. 문자열, 40자 이하. **이미 있는 항목 이름과 같으면(대소문자 · 띄어쓰기 차이 무시) 그 항목에 카드가 추가된다.** 새 이름이면 새 항목이 생긴다. |
| `cards` | O | 카드 배열, 1–200개. |
| `cards[].front` | O | 문제(앞면). 300자 이하. 문장 부호만으로 된 앞면은 안 된다. |
| `cards[].back` | O | 정답(뒷면). 300자 이하. |
| `cards[].note` | X | 설명 · 예문 · 힌트. 500자 이하. 답을 낸 뒤 참고용으로 보인다. |

### 자동 채점 방식 (뒷면 쓰는 법에 중요)
- 비교 전에 양쪽 모두: 유니코드 NFKC, 영문 소문자화, **가타카나 → 히라가나**, 공백과 문장 부호(`、。・「」『』！？!?.,:;'"~〜…()（）[]-` 등) 제거.
  → 띄어쓰기 · 대소문자 · 마침표 · 가타카나/히라가나 차이는 신경 쓰지 않아도 된다.
- 뒷면을 `/` 또는 `;` 로 나누면 **각 부분도 정답**으로 인정된다. 같은 답의 다른 표기(한자/가나, 줄임말)를 이렇게 적는다.
  예: `"お疲れ様でした / おつかれさまでした"`
- 그래서 **뒷면은 짧은 정답만** 적는다. 설명 · 괄호 해설 · 예문은 `note` 로 보낸다. (괄호도 지워질 뿐 내용은 남아 비교되므로, 뒷면에 괄호 설명을 넣으면 자동 정답이 거의 안 나온다.)
- 앞면은 답이 하나로 좁혀지게 쓴다. 뜻이 여러 개인 표현이면 앞면에 상황 · 뉘앙스를 괄호로 적는다(앞면 괄호는 상관없다).

### 중복
- 같은 항목 안에서 앞면이 같으면(위 정규화 기준) 중복으로 건너뛴다. 파일 안 중복도 마찬가지.
- 같은 앞면에 답이 여러 개면 카드를 나누지 말고 뒷면에 `/` 로 묶는다.

## 2. 한자 추가

```json
{
  "track": "kanji",
  "notes": [
    { "kanji": "鬱", "on": ["ウツ"], "kun": ["ふさ.ぐ"], "meanings_ko": ["우울하다", "울창하다"], "hunum_ko": "답답할 울", "jlpt": 1 }
  ]
}
```

| 키 | 필수 | 규칙 |
|---|---|---|
| `kanji` | O | 한자 **한 글자**. |
| `on` | O | 음독 배열, **가타카나**(장음 `ー` 가능). 없으면 `[]`. |
| `kun` | O | 훈독 배열, **히라가나**. 오쿠리가나 경계는 `.`(예 `た.べる`), 접두/접미는 `-`. 없으면 `[]`. `on` · `kun` 둘 다 비면 안 된다. |
| `meanings_ko` | O | 한국어 뜻 배열, 1–20개, 각 300자 이하. |
| `hunum_ko` | X | 훈음 `"<훈> <음>"`, 음은 한글 한 음절(예 `"먹을 식"`). |
| `jlpt` | X | 정수 1–5. |

- 다른 필드(`examples`, `sentences`, `strokes` 등)는 **넣으면 오류**다.
- 채점: 읽기 문제는 음독 · 훈독 중 하나와 맞으면 정답. 뜻 문제는 `meanings_ko` 항목 중 하나와 (공백 · 괄호 내용 무시하고) 같으면 정답 → **뜻은 짧은 낱말로**, 항목 하나에 한 뜻.
- **앱에 이미 상용 한자 약 2200자가 있다**(JLPT N5–N1 범위 대부분). 같은 글자는 중복으로 건너뛰므로, 한자 파일은 드문 한자에만 쓴다.

## 3. 토익 단어 추가

```json
{
  "track": "toeic",
  "notes": [
    { "word": "reconcile", "pos": "verb", "meaning_ko": "(장부를) 맞추다, 조정하다", "example_en": "Please reconcile the account before the audit.", "example_ko": "감사 전에 계정을 맞춰 주세요." }
  ]
}
```

| 키 | 필수 | 규칙 |
|---|---|---|
| `word` | O | 영어 단어/구. 영문자로 시작, 영문자 · 공백 · `'` · `.` · `-` 만. 300자 이하. |
| `meaning_ko` | O | 한국어 뜻. 여러 뜻은 `,` `;` `·` `/` 로 구분 → 각 뜻이 따로 정답 인정. |
| `example_en` | O | 영어 예문. **`word` 를 그대로(활용형 말고 같은 철자로) 포함**해야 한다. 빈칸 채우기 문제에 쓰인다. |
| `example_ko` | O | 예문 번역. |
| `pos` | X | 품사(예 `noun`, `verb`, `adjective`). |

- 다른 필드는 넣으면 오류다.
- 빈칸 채우기는 `word` 와 똑같이 입력해야 정답이므로, 예문에서 단어 형태를 바꾸지 않는다(`reconciled` ✗ → `reconcile` ✓).
- **앱에 이미 TOEIC 기본 어휘(TSL) 1250개가 있다.** 같은 단어(소문자 · 공백→`-` 기준)는 중복으로 건너뛴다.

## 4. 제한과 결과

- 파일 하나 200개, 파일 올리기로 하루 200개(04:00 기준), 1MB.
- 올리면 카드마다 결과가 나온다: `추가됨` / `형식 오류`(사유 목록) / `중복` / `하루 제한 초과`.
- 오류가 난 카드만 고쳐 **같은 파일을 다시 올려도 된다** — 이미 들어간 카드는 중복으로 건너뛴다.
- 파일 최상위 형식이 틀리면(키 섞임, 배열 비어 있음, 201개 이상) 파일 전체가 거절된다.

## 5. 내보내기 전 점검표

- [ ] 최상위 키가 `deck`+`cards` 또는 `track`+`notes` 중 한 쌍뿐인가
- [ ] 카드 ≤ 200개, 표에 없는 키 없음, `id` 없음
- [ ] (앞뒤 카드) 뒷면은 짧은 정답만, 대체 답은 `/` 로, 설명은 `note` 로
- [ ] (앞뒤 카드) 같은 앞면 반복 없음
- [ ] (한자) 한 글자, 음독 가타카나 · 훈독 히라가나, 뜻은 배열
- [ ] (토익) 네 필드 모두 있음, 예문에 단어가 같은 철자로 들어 있음
- [ ] 사실 확인: 뜻 · 읽기 · 번역이 정확한가. 확신이 없는 카드는 빼고 사용자에게 알린다
- [ ] 출력은 JSON 코드 블록 하나 (사용자가 그대로 `.json` 으로 저장)
